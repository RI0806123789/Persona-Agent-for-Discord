# ver0.1.4 — 2026/07/16

## 永続化データを SQLite データベースへ移行

`memory/` 配下の構造化データ（`affinity.json` / `user_stats.json` / `queue.json` / `pending_log.txt`）と プロフィール記憶（`profile.json`）を、単一の SQLite データベース `memory/bot.db` に統合しました。SQL 文は新設の `database.py` に集約しています。`projects.json` は LLM が構造を自由に決める記憶のため、従来どおり JSON ファイルのまま扱います。

- **旧データの自動移行**: 初回起動時に旧 JSON / テキストファイルを DB へ取り込み、`<元の名前>.imported.bak` に改名して保全（二重取り込み防止＋バックアップ）
- **profile.json は手書き追加用の受け皿に**: 起動のたびに `profile.json` の中身を DB の `profile` テーブルへ自動マージ（同名キーはファイル側が優先）し、ファイルを `{}` に戻す。**ユーザーが `profile.json` に事実を書き足して再起動するだけで、ボットの記憶へ追加される**
- **スキーマ移行機構**: `PRAGMA user_version` によるバージョン管理を導入。将来列を追加したくなったら `SCHEMA_VERSION` を上げて `_MIGRATIONS` に `ALTER TABLE` 文を1行追記するだけで、既存 DB にも自動適用される
- **クラッシュ耐性の向上**: 書き込みがトランザクションで原子的になり、旧方式の「ファイル全体上書き中のクラッシュでデータ破損」リスクを解消
- **WAL モード**: ボット稼働中でも `sqlite3` CLI などから安全に中身を読める
- **文書キューの堅牢化**: タスクの取得（claim）を SELECT + UPDATE の同一トランザクションで行い、二重取得を構造的に防止
- 記憶圧縮のしきい値を「行数」から「Q/A 件数」（`MEMORY_FLUSH_THRESHOLD_ENTRIES`）に変更

## 全機能を `/functions` パネルに統合（UI刷新）

`/status`・`/graph`・`/ng_reload`・`/unblock` と後述の会話要約を、単一の `/functions` コマンド（機能ハブ）に統合しました。Discord の View は最大5行までのため1枚のパネルに合体できないので、ボタンで選んだ機能のパネルへ同じメッセージを差し替える方式を採用しています。

- `/functions` を実行すると、本人だけに見える（エフェメラル）ハブパネルが開く
- **⚙️ キャラ設定** / **📋 会話要約** … パネルを開く（同じメッセージが変身）
- **📊 グラフ** / **🔄 NGワード再読込** … その場で実行し、別のエフェメラルメッセージで結果を返す
- **🚫 ブロック解除**（旧 `/unblock`・**管理者専用**） … `ng/blacklist.json` を直接編集せず、ブロック中ユーザーの選択メニューから解除し違反カウントもリセット。管理者以外にはボタン自体を非表示（従来は権限が無い場合に警告を返信していた）
- キャラ設定パネル（旧 `/status`。「設定」から「キャラ設定」にリネーム）を含め、すべてのパネルをエフェメラル化（従来 `/status` は全員に見えていた）
- **🔍 Google検索** トグルをキャラ設定パネルから機能パネル（ハブ）へ移動し、確定操作なしでその場で切り替えられるように
- 各パネルの「キャンセル/閉じる」を「**↩️ 戻る**」に変更し、機能パネルへ戻って別の機能を続けて使えるように
- 旧コマンド `/status`・`/summarize`・`/graph`・`/ng_reload`・`/unblock` を削除し `/functions` に集約

## チャンネル会話の議事録要約機能を追加

`/functions` → **📋 会話要約** から、テキストチャンネルの会話を発言者名つきの議事録として要約できます。要約はキャラ設定パネルで選択中のモデル・ペルソナを使用し、冒頭と締めだけキャラ口調、本編は正確で中立的な文体で生成します。

- 期間を **1時間 / 12時間 / 1日 / 1週間 / 1か月** から選択
- 表示範囲を「全員に表示」「自分だけ」から選択
- 発言者は表示名（`display_name`）で判別（他の BOT は除外、自ボットは文脈として含める）
- 決定事項・TODO・保留を抽出。Markdown を使わず Discord で読みやすいプレーンテキストで出力
- 対象メッセージが上限（1000件）を超える場合は要約せず自動停止
- 生成結果は感情タグ・見出し記号の除去、NGワードマスク＋AIモデレーションを経て送信

## ユーザー別会話統計ダッシュボードを追加

`/functions` → **📈 会話統計** から、ユーザーごとの会話傾向をグラフでダッシュボード表示できます。集計対象は「ボットへの発言のみ」で、`handle_chat_message` の直前に fire-and-forget で記録します（失敗してもチャット本体は止めないフェイルオープン設計）。**すべてエフェメラル（非公開）で表示されます。**

- **集計データ**: ユーザーごとに累計発言回数・時間帯別ヒストグラム（`Asia/Tokyo` の「時」に変換した 24 時間分）・直近発言サンプル（50 件のリングバッファ）を記録
- **話題・性格の LLM 解析**: 直近サンプルを Gemini に渡し「よく話す話題」と「ビッグファイブ性格特性」を JSON で推定。結果は 24 時間キャッシュし、TTL 内は再計算しない（呼び出し・パース失敗時は既存キャッシュにフォールバック）
- **項目別グラフ**（matplotlib）: 時間帯＝棒グラフ / 話題＝重み付き横棒 / 性格＝ビッグファイブのレーダーチャート。項目セレクトで「全部 / 時間帯 / 話題 / 性格推定」を切り替え可能
- 性格推定は直近サンプルが 10 件未満のとき「データ不足」として描画をスキップ（推定である旨も明記）
- **権限**: 一般ユーザーは**自分の統計のみ**閲覧可。**管理者のみ**、ユーザー選択メニューで他メンバーの統計を閲覧でき、発言回数ランキング（全体比較）も表示可能
- データは `memory/bot.db` の `user_stats` テーブルに永続化され、`asyncio.Lock` で対象ユーザー1行の保存を直列化（ボット再起動でもリセットされない）
- 調整値（TTL・上限・タイムゾーンなど）は `constants.py` の `STATS_*` に集約

## 自発的な会話機能を追加

`/functions` → **💬 自発会話** から有効化すると、一定時間会話が無いチャンネルへ、過去の話題をもとにボットの方から話しかけます。

- 無会話しきい値を **1時間 / 3時間 / 6時間 / 12時間 / 24時間** から選択（デフォルト: OFF・6時間）
- 対象はボットが会話に参加したことのあるテキストチャンネル（自動登録。DM は対象外）
- ボット宛てでない発言も「会話」としてカウントし、会話が活発な間は割り込まない
- 一度話題提供したら、誰かが発言するまで同じチャンネルには再投稿しない（沈黙中の連投防止）
- 話題は選択中のペルソナ・モデル＋チャンネル履歴＋長期記憶（プロフィール）から生成し、NGワードマスク・AIモデレーションを通過したものだけを投稿（不適切と判定された場合は投稿自体を見送り）
- 設定・監視状態はインメモリのみで、ボット再起動でリセットされる（再起動後はデフォルトの OFF に戻る）

## Linux / Ubuntu 対応

読み上げ用の FFmpeg 解決が Windows 専用（`index/ffmpeg.exe` に固定）だったため、Linux では `/join` の読み上げが必ず失敗していました。「`index/` 内のバイナリ」→「PATH 上の `ffmpeg`」の順に探索するよう変更し、`sudo apt install ffmpeg` だけで動くようにしました。

- FFmpeg が見つからない場合もエラーにせず、読み上げのみスキップ（チャット機能は通常どおり動作するフェイルオープン設計）
- 探索結果は起動中変わらないため `lru_cache` で1度だけ解決
- README のセットアップ手順を Windows / Ubuntu 別に整理し、仮想環境（venv）の作成手順を追加

## バグ修正

**重大:**

- **空メッセージ送信によるクラッシュを修正** (`bot.py`): モデルが感情タグ `[V:X, A:Y]` のみを返した場合、タグ除去後の本文が空になり `message.reply("")` で Discord API が例外を投げていた問題を修正。本文が空のときは代替メッセージを返すガードを追加。

**中程度:**

- **記憶処理のハング対策** (`memory_service.py`): 記憶カテゴリのルーティング判定（`route_category`）と記憶圧縮（`_compact_memory`）の Gemini 呼び出しにタイムアウトが無く、API がハングすると応答全体（および以降の記憶書き込み）が固まる恐れがあった問題を修正。他の呼び出しと同様に `asyncio.wait_for` でタイムアウトを付与。
- **ネスト JSON のパース失敗を修正** (`storage.py`): `extract_json_object` のフォールバックが非貪欲な正規表現でネストした JSON（`{"profile":{...},"projects":{...}}`）を途中で切ってしまう問題を、波括弧の対応と文字列リテラルを考慮した抽出処理に置換して修正。
- **文書キュー（`queue.json`）の肥大化を修正** (`document_service.py`): 完了・失敗したタスクが削除されず無限に蓄積し、ワーカーの読み込みコストが増大していた問題を修正。終了タスクを直近50件に自動で切り詰め。
- **中断タスクの取り残しを修正** (`document_service.py`): 処理中（`processing`）に Bot が停止したタスクが再起動後に二度と処理されず放置される問題を修正。起動時に `processing` を `pending` へ戻す復旧処理を追加。
- **グラウンディング応答のトークン数が常に0で記録される問題を修正** (`usage_graph.py`): Google検索（REST API 経路）の使用量メタデータは camelCase の辞書形式で返るが、SDK 形式（snake_case 属性）でしか読み取っていなかったため、`/graph` の統計にグラウンディング応答が常に 0 トークンとして記録されていた。両形式に対応。
- **DM からの文書添付が必ず失敗する問題を修正** (`document_service.py`): 文書ワーカーのチャンネル種別チェックに DM チャンネルが含まれておらず、DM で受け付けた文書タスクが処理段階で必ずエラーになっていた。`on_message` 側と同じ判定（`is_supported_message_channel`）に統一。
- **画像添付時に Google 検索が無効になる問題を修正** (`gemini_service.py`): グラウンディング有効かつ画像ありの場合、SDK 経路に grounding フラグが渡されず、検索なしで応答していた。SDK 側のグラウンディングツールを使用するよう修正。
- **日本語文書の検証失敗を修正** (`document_service.py`): テキスト文書の検証で先頭4096バイトのみをデコードしていたため、マルチバイト文字（日本語）が境界で分断されると正常なファイルでも `UnicodeDecodeError` で拒否されていた問題を修正。末尾の不完全な文字のみ許容するインクリメンタルデコードに変更（バイナリファイルは引き続き拒否）。

**軽微:**

- **モデレーション判定の正規化** (`content_moderator.py`): モデルが `{"safe":"false"}` と文字列で返した場合に `bool()` が True 扱いとなり安全と誤判定していた問題を修正。真偽値へ明示的に正規化。
- **グラウンディングのフォールバック修正** (`gemini_service.py`): SDK フォールバック時に旧世代（gemini-1.5 系）専用の `google_search_retrieval` を使い必ず失敗していた問題を、対応する `google_search` を優先するよう修正。
- **グラウンディング時のモデル選択を反映** (`gemini_service.py`): グラウンディング有効時に設定パネルで選んだモデルが無視され固定モデルが使われていた問題を修正。選択モデルを使用し、失敗時のみ既知の対応モデルへリトライ。
- **ソース抽出時の例外を修正** (`gemini_service.py`): grounding source の `title` を未チェックでアクセスし、欠落時に以降のソースが失われていた問題を `getattr` で安全化。
- **親密度データの保存競合を修正** (`affinity_service.py`): 短時間に複数の保存処理が並行実行され `affinity.json` が壊れる恐れがあった問題を、ロックによる直列化で修正。
- **トークン履歴のメモリ増加を抑制** (`usage_graph.py`): 利用トークン履歴が起動から無制限に蓄積していた問題を、直近500件のリングバッファ化で抑制。
- **メッセージ分割時の区切り文字残りを修正** (`discord_helpers.py`): 長文分割時に次チャンク先頭へ区切りスペースが残る問題を修正し、区切り文字が無い強制カット時に文字が失われないよう整理。
- **ログ出力順の修正** (`bot.py` / `document_service.py`): 生成失敗（`None`）時に `AI：None` とログ出力されていたノイズを、`None` 判定後にログするよう順序変更。
- **TTS が参考リンクの URL を読み上げる問題を修正** (`bot.py` / `document_service.py`): グラウンディングの参考リンクを本文に連結してから TTS・長期記憶に渡していたため、URL の列挙が読み上げと記憶ログに混入していた。リンクは Discord への送信テキストにのみ追記するよう分離。
- **再接続毎のコマンド同期を抑止** (`bot.py`): `on_ready` は再接続のたびに呼ばれるため、レート制限の厳しい `tree.sync()` が毎回実行されていた。初回のみ同期するよう修正。
- **NGワードの部分マスクを修正** (`ng_word_service.py`): 短い語が長い語より先にマッチするため、長い NG ワードが部分的にしかマスクされないことがあった。長い語を優先する最長一致に修正。
- **会話リセット後の履歴欠落を修正** (`discord_helpers.py`): リセットポイント指定時に古い順で履歴を取得していたため、リセット以降の発言が上限（100件）を超えると最新の発言がプロンプトに入らなくなっていた。常に直近の発言を取得するよう統一。
- **設定パネルのタイムアウト後の UI 残留を修正** (`settings_view.py` / `commands.py`): タイムアウト後も操作できないボタンが残り、押すと「インタラクションに失敗しました」と表示されていた。タイムアウト時にパネルを時間切れ表示へ置き換えるよう修正。
- **文書応答の空文字ガードを強化** (`document_service.py`): 応答が空文字の場合に空メッセージ送信で例外になる恐れがあったのを、失敗扱いに統一。
- **感情タグの露出を修正** (`bot.py`): モデルが `[V: +5, A: -10]` のように空白を含む形式でタグを出力すると、抽出されずタグがそのまま返信に表示され感情も更新されなかった問題を修正。空白を許容する正規表現に変更。
- **参考リンクにタイトルを表示** (`discord_helpers.py`): グラウンディングのソース表示がリダイレクト用の無機質な URL のみで、抽出済みのページタイトルが使われていなかった問題を修正。`[タイトル](URL)` 形式でリンク先が分かるように表示。
- **文書ワーカーの永久停止を修正** (`document_service.py`): キューの読み書きで予期しない例外（一時的なファイルロック等）が発生するとワーカーが停止し、以降の文書添付が二度と処理されなくなる問題を修正。ループ全体を保護してリトライするよう変更。
- **設定パネルの「キャンセル」で失敗表示が出る問題を修正** (`settings_view.py`): インタラクションへ応答せずにパネルを削除していたため、クライアント側に「インタラクションに失敗しました」と表示されることがあった問題を修正。
