# ver0.1.6 — 2026/08/14

## キャラクター別ボイス

読み上げエンジンを gTTS から **edge-tts**（Microsoft Edge のニューラル音声。APIキー不要）へ切り替え、ペルソナごとに話者・声の高さ・速さ・音色を変えられるようにしました。

- **男性話者に対応**（オジサン／クレーマー／ショタの3キャラ、残り9キャラは女性話者）。従来は女性話者しかなく、男性キャラは声を無理にピッチダウンして不自然になっていた問題を解消
- 声の高さ・速さは edge-tts 側のパラメータで指定し、edge-tts にない音色（EQ）だけを新設の `voice_dsp.py`（numpyのみの軽量バイクアッドフィルタ）が担当。ピッチを変えても声質が崩れない
- 各ペルソナの声設定（話者・pitch・rate・音色）は `constants.py` の `VOICE_PROFILES` に集約。実測に基づく較正値のため、コード側では計算せず値を直書きしている
- edge-tts が失敗した場合は自動で gTTS へ退避（キャラ差は失われるが読み上げ自体は止まらない）

## 新機能

- **リマインダーの繰り返し**（毎日／毎週／毎月）: 会話から繰り返し種別も読み取って登録。既存の統合判定に相乗りさせ、Gemini呼び出しは増やしていない
- **リアクション（👍👎）によるフィードバック収集**: チャット返信に自動で付与し、モデル・ペルソナ別の評価を集計（閲覧は管理者専用・エフェメラル）
- **オンボーディング導線**: `/functions` → ❓使い方 パネルと、サーバー参加時のウェルカム投稿を追加
- **会話統計の収集停止（opt-out）**: `/functions` → 🔒統計プライバシー から、本人が統計収集の停止と蓄積データの削除を行えるように
- DBスキーマを v8 まで更新（`reminders` の繰り返し列、`feedback` テーブル、`user_stats.stats_opt_out` 列を追加。起動時に自動適用）

## 運用・構成の整備

- **systemdサービス化**: 本番環境をsystemd管理下に置き、異常終了時の自動復帰とサーバー再起動時の自動起動に対応（`deploy/bot.service`）
- **APIキー管理を `.env` へ移行**: 旧 `config.py` / `config_private.py` を廃止し、専用形式の `.env` に統一。既存環境向けの移行スクリプト `deploy/migrate_config_to_env.py` を追加
- **FFmpegバイナリを削除**: ver0.1.5でコード上の依存はゼロになっていたが、リポジトリに残っていた約439MiBのバイナリを削除

## 不具合修正

- **私的な記念日が公開チャンネルへ投稿される問題を修正** (`auto_topic_service.py`): 公開してよい記念日の許可リスト `ANNIVERSARY_PUBLIC_LABELS` が定義されているだけで実装から参照されておらず、「退院記念日」のように DM でだけ話した私的な記念日もそのまま自動お祝いの対象になっていた。許可リストと完全一致するラベルだけを投稿対象にした（対象外の記念日も記憶としては保持する）
- **ボイス読み上げがボット再起動まで停止することがある問題を修正** (`voice.py`): 再生完了待ちに上限が無く、ボイス接続が正常な切断を経ずに切れて `after` コールバックが呼ばれないと、そのサーバーの読み上げワーカーが永久に待ち続けていた。「音声の再生秒数 ＋ `TTS_PLAY_TIMEOUT_MARGIN_SECONDS`」を上限に打ち切り、次の読み上げへ進むようにした
- **記憶圧縮中に他ユーザーの会話ログ追記が最大約150秒ブロックされる問題を修正** (`memory_service.py`): `io_lock` を保持したまま Gemini を呼んでいたため、圧縮中は無関係なユーザーの記録まで待たされていた。ロックはファイルI/O・DB書き込みの直列化だけに使い、Gemini 呼び出し中は手放す形に変更。あわせて、待っている間に追記された会話ログや文書要約を巻き込んで消さないよう、一時ログの削除範囲を圧縮対象の行までに限定する `pending_clear_upto()` を追加した（スキーマ変更なし）
- **モデレーションの応答取得失敗が通過扱いになることがある問題を修正** (`content_moderator.py`): 独自実装の例外捕捉が `AttributeError` を取りこぼし、「原因不明の取得失敗は弾く」という安全側の分岐を通らずに通過していた。規約どおり `storage.safe_response_text` 経由で読むよう統一
- 会話要約パネルのタイムアウト案内が、削除済みの旧コマンド `/summarize` を案内していた問題を修正（`/functions` へ）
- メッセージ履歴を読む権限が無いチャンネルで、入力中表示だけが出て完全に無応答になる問題を修正
- 会話要約の時刻が実行環境のローカルタイムゾーンに依存し、UTC運用のサーバーでは9時間ずれていた問題を修正（`Asia/Tokyo` 固定に）
- 音色（EQ）の設定ミスが音声の破壊やクラッシュに直結しないよう、値の範囲チェックとフェイルセーフを追加

## 内部整理

見回りタスク・長文送信・管理者判定などの重複コードを共通化するための受け皿関数を追加し、このうち**見回りタスクとパネル UI は呼び出し側の置き換えまで完了**した（長文送信・管理者判定は次バージョン以降）。そのほか調整値の `constants.py` への集約や、陳腐化したコメント・未使用コードの整理を行った。

- **見回りループ** (`bot.py`): 5つの定期タスク（記憶圧縮・自発会話・記念日・リマインダー・フィードバック整理）へ手書きでコピーされていた `tasks.loop` + `before_loop` + try/except の3点セットを、`background.make_guarded_loop()` の呼び出しへ統一
- **パネル UI**: `FunctionsView` / `SettingsView` / `SummaryView` / `StatsView` / `AutoTopicView` / `ReminderView` / `UnblockView` を `view_parts.PanelView` 継承へ移行し、各パネルに重複していた `on_timeout()` とパネル差し替えの定型処理を `swap_panel()` / `refresh_items()` へ集約（表示・操作の挙動は変更なし）
- **プロンプト文面**: 記憶ルーティング・記憶圧縮・文書要約・統計解析・親密度の5つのプロンプトが `prompting.py` と各サービスの2箇所に同じ文面で存在し、`prompting.py` 側だけを直しても実際の送信内容には反映されない状態だった。各サービスから `prompting.py` の関数を呼ぶ形へ統一
- **曜日名テーブル** (`content_moderator.py` / `reminder_service.py`): 独自定義していた曜日名を削除し `timeutil.format_weekday()` へ統一（リマインダーの登録時プロンプトと通知文で曜日表記が食い違うのを防ぐ）
