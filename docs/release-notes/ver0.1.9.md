# ver0.1.9 — 2026/11/02

## 新機能

- **README の紹介動画**: README の冒頭に、ボットの紹介動画を表示する節を追加した。動画は GitHub が発行するアドレスで埋め込み、リポジトリにファイルを置かない。
- **ボイスチャンネルでの音声会話（Gemini Live）**: `/join` で呼んだボイスチャンネルで、ボットと声で会話できるようにした。参加者の声を受信して Gemini Live（`gemini-3.8-live`）へ流し、返ってきた音声を再生する。受信は追加のライブラリを使わず、discord.py の受信口・PyNaCl・davey（DAVE の復号）・Opus で組んだ。ボイスチャンネルの全員が同意パネルで同意するまで一時停止し、記憶・親密度への反映は別の任意の同意（初期オフ）にした。複数人の発言はユーザーごとに見分けて1人ずつ送り、順番待ちと割り込みに対応する。入出力の文字起こしを NG ワードと AI モデレーションで並行して確認し、違反なら再生を止める。セッションの再開・文脈の圧縮・回数制限つきの再接続に対応し、利用枠の超過では再接続しない。同時に会話できるのは2か所まで。テキストの返信の読み上げは廃止し、読み上げ（edge-tts / gTTS）は自律行動の配信だけで使う（#268）。
- **サブエージェントの作業スレッド**: 委任するとき、依頼メッセージに作業スレッドを作り、ペルソナが任せる内容をボットの名義で伝え、サブエージェントが Webhook で名前とアイコンを変えて開始・手順ごとの進捗・報告を1通ずつ残す。中止ボタンはスレッドの依頼メッセージに付き、失敗・中止は元のチャンネルにも知らせる。DM・スレッドの中・ボイスのチャット・権限不足や作成の失敗では従来の返信1通の書き換えへ切り替える。Webhook はチャンネルごとに1つを使い回し、子の表示名・アイコンと文面は `personas.json` の `agent` で設定できる。子の発言は NG ワードを伏せ、メンション通知を出さない（#267）。
- **自律行動の配信先の指定**: 管理者が `/functions` → ⚙️ キャラ設定 → 🎙️ 配信先 で、自律行動で入るステージ・ボイスチャンネルを1つずつ指定できる。ステージの指定を優先し、削除済み・権限不足で使えなければボイスの指定、最後に従来の自動選択へ戻す。確定時は最新の管理者権限を確認してからスキーマ15の新しい列へ保存する。パネル・❓ 使い方・ウェルカム投稿に、手動でのチャンネル移動は防げず移された場合は配信を終える旨を明記した（#266）。

## 不具合修正

- **委任中断と配信先の画面表示**: 読込済み画像をサブエージェント委任後の親の応答にも引き継ぐ。タスク中断時は作業の回収に加えて中止ボタンを外し、ボタン操作も終了処理の管理下で実行する。配信先パネルの「戻る」はキャラ設定へ戻す。管理コンソールにも指定済みのステージ・ボイスの配信先を表示し、伏せ字モードを適用する（#292）。
- **ボイス操作と移動後の配信終了**: 追越し通知が失敗した後でも、後続操作の中断で元の参加・退出が復活して成功した場合はエラー扱いにしない。自律配信の外部移動後に音声接続が確立しなくても、締めの通知・所有ステージ枠の終了・セッションの回収を行う（#289）。
- **読み上げの日本語と代替合成**: URL直後に空白なしで続く日本語を読み上げ本文に残す。edge-ttsが応答しない場合は10秒でgTTSへの退避へ進み、終了済み配信の待機音声をキュー上限の判定前に除く。停止・切断時のキャンセルは従来どおり伝える（#290）。
- **日時・感情タグ・記念日の境界処理**: UTCへ変換できない極端な日時はリマインダー登録を見送り、通常会話を続ける。感情タグは末尾の連続したメタデータだけを採用・除去し、本文中の引用を残す。記憶圧縮は保存直前のDBの記念日と統合し、生成待機中の追加・訂正・削除を古い生成結果で巻き戻さない（#291）。
- **文書要約と調査報告の安全確認**: 文書要約をNGマスクとAI判定に通し、最終返信も安全と判定された場合だけ長期記憶へ保存する。子の調査報告は参考リンクを含めて公開前に独立して判定し、拒否された報告はスレッドにも親の生成にも渡さない。通常・文書の参考リンクもNGマスクし、文書要約用のファイル名は改行・制御文字・区切り表記を無害化する（#286）。
- **画像コメントの受付と定型文の書式検証**: 本文なしの画像コメントも、ダウンロード・展開の前に配信コメントの受付制限を適用する。読込を始めた無効添付もクールダウンの対象とし、配信終了時の通常会話への切替と画像の回収を維持する。`personas.json`の進捗文は許可した差し込み名だけを受け付け、巨大な文字列を作る幅指定や変換指定を実行せず拒否する（#287）。
- **管理画面の伏せ字と配信先パネルの権限**: 中止時のステージ名と`user_id`も伏せ、旧プロフィール統合ログは件数だけを出力する。ログ接続のSSHエラーは安全な文面を画面・ツールチップへ引き継ぐ。配信先パネルを開く際も応答保留後に最新の管理者権限を確認し、失効・確認失敗時は設定を表示しない（#288）。
- **チャンネル履歴の除外と区切り偽装対策**: 通常会話・委任の判定・文書返信・自発会話・記念日・自律行動・会話要約へ渡す履歴から、現在ブロック中の利用者と他ボットを除き、自ボットの返答は維持する。発言本文などの見出し・ロール行を全角化し、コードが付けた正規のロールと区切りを保つ。追加のAI呼び出しは行わず、応答用の履歴の取得・整形に失敗した場合は履歴なしで会話を続ける。入力の無害化だけでAIへの判定誘導を完全に防げるものではない（#281）。
- **NGワードの表記ゆれ判定と元本文のマスク**: 登録語と本文を同じNFKC・casefold・ひらがな統一で照合し、ゼロ幅文字や非空白の制御文字を除いて検知する。正規化後の一致を元の文字位置へ戻し、周囲の文面と元の文字数を保って伏せる。空白・区切り記号は保持し、最長一致の優先・1回の正規表現コンパイル・再読込のスナップショット差し替え・検出した原文の出現順を維持する（#282）。
- **確認返信とボイス案内の通知先**: リマインダー登録確認とチャンネル名を含む公開案内で、本文中の全体・ロール・他ユーザーへのメンション通知を禁止する。登録確認はNGワードを伏せ、依頼者への返信通知は維持する。クライアントの既定でも本文中の通知を制限し、記念日・リマインダー配信は従来どおり対象者本人だけを個別に許可する（#278）。
- **全体ブラックリストの閲覧・解除権限**: サーバー管理者が他サーバーの違反者を閲覧・解除できた問題を修正し、一覧・解除・設定画面の登録人数をボット所有者に限定する。表示時と解除直前に所有者を再確認し、旧形式の全体ブロックは維持する（#279）。
- **統合判定の入力と抽出結果の扱い**: 固定の判定指示をシステム指示へ移し、本文と委任時の会話履歴をエスケープしたデータとして分離する。JSONスキーマと抽出文字列の検証を加え、不正なリマインダー・委任内容を実行に使わない。判定失敗時に会話を通す方針は維持する。入力の分離だけでAIへの判定誘導を完全に防げるものではない（#280）。
- **接続・会話の失敗時の扱い**: `/join`のエラーは内部の例外本文を伏せ、通常会話の設定ファイル名も利用者へ表示しない。接続失敗後は今回の半接続状態だけを片付け、好感度は返信の送信成功後だけ更新する（#262）。
- **管理コンソールの実効設定とエラー表示**: 廃止されたモデルなど選択肢外の保存値は、ボットと同じ既定値で表示する。ログ取得の失敗時は追加検索を見送り、同じエラー文の重複表示を防ぐ（#259）。
- **旧会話統計の移行**: 統計の保存変換を共通化し、旧JSONの`opt_out`・`stats_opt_out`も取り込んで収集停止設定を保持する。通常保存・全件置換も同じ9列を扱う（#260）。
- **読み上げ待機列の整理**: 非同期待機を使わない読み上げキューを`deque`へ変更し、内部の未完了カウンタの増加を解消する。待機順・上限超過時の新規依頼の見送り・接続切替時の古い待機分の破棄を維持する（#261）。
- **ステージへの復帰失敗時の退出**: ボイス接続先の保護で、復帰先の閲覧権限も `/join` と同じく確認する。ステージへ戻った後に発言者へ昇格できなければ、対象の接続・保護登録を照合して退出し、待機中に差し替わった接続や再登録された保護情報は保持する（#258）。
- **配信終了直後の通常会話**: 受付前に配信が終わった発言は通常のサブエージェント判定へ戻し、通常枠の確保後に話題提供の監視へ登録する。本文なし添付の画像確認中に配信が終わった場合も、文書受付・画像の失敗案内を行う（#256）。
- **自動投稿の送信権限の再確認**: 話題提供・記念日のお祝いで、履歴取得後と送信前にもボット自身の閲覧・送信権限を確認する。生成前の権限喪失ではAPIを呼ばず再試行可能にし、生成後は投稿を見送って同じ沈黙期間・当日の再生成を抑える（#257）。
- **パネル操作時の管理者権限**: 会話統計の項目・対象切替と機能ハブへ戻る際に、操作時点の権限を反映する。権限を失った利用者には他人の統計の対象名・候補・管理者ボタンを表示せず、ブロック解除は応答待機後も最新の権限を確認する（#255）。
- **繰り返しリマインダーの取消**: チャンネル取得・スレッド再開・別の通知の待機中に取消が成功したら、未送信の通知と次回予告を送らない。送信開始済みなら今回の送信完了を待って次回以降を止める（#252）。
- **会話統計の保存失敗**: 発言記録・収集設定・蓄積データ削除・AI解析は保存成功後だけメモリへ反映し、失敗や中断した操作による過去の統計の消失と収集設定の不一致を防ぐ（#253）。
- **サーバー再参加時の設定復元**: 再起動せず同じサーバーへ再参加しても、保存済み設定と記念日の投稿記録を復元する。1項目の変更による他の設定の初期化と、同日の記念日の再投稿を防ぐ（#254）。
- **管理コンソールのサービス操作の終了確認**: 起動・停止・再起動がSSHの応答期限を超えても、遠隔コマンドとsystemdジョブの終了を確認するまで後続の操作・デプロイを待機する。終了を確認できなければ状態不明を保持し、手動確認まで更新操作を拒否する（#250）。
- **参加サーバー一覧のページング**: 200件を超えるサーバーと保存設定も取得する。後続ページの失敗・取得上限・時間切れは一部取得として表示し、取得済みの情報を残す。ボイス状態の追加照会にも件数・時間の上限を設ける（#251）。
- **UIパネルのコールバックと終了処理の連携**: `/functions` 等で開く UI パネルのボタン操作（コールバック）が、ボット終了時のタスク回収に登録されておらず、応答保留中に終了すると DB を閉じた後もコールバックが進み保存に失敗する問題を修正。`PanelView._dispatch_item` をオーバーライドし、コールバック実行を `TaskOwner.run()` 経由で所有者管理下に置き、終了開始後の新規操作を拒否し、実行中処理を共有接続のクローズ前に回収するようにした。
- **Live 会話の検索付き接続の誤判定**: Live の Google 検索は無料枠に含まれず、検索ツールを付けた接続だけが「quota を超えた」と拒否されることがある。これを利用枠の上限と判定して `/join` が退出していたため、検索付きの接続が超過で拒否されたときに限り、検索だけを外して1回だけ接続し直す（声と会話は維持する）。検索なしでも超過なら従来どおり本物の超過として終了する。再接続のときも同じ。

## 内部修正

- **Windows の依存監査の文字コードを修正**: pip-audit が日本語コメント入りの requirements を既定コードページで読み、検査前に失敗する問題に対し、監査ジョブを UTF-8 モードで実行する（#285）。
- **依存の脆弱性の継続的な検出**: `.github/dependabot.yml` を追加し、ボット・管理コンソールのバックエンド（pip）、画面（npm）、CI の actions の更新を毎週提案させる。`cooldown` で公開から14日未満の版は提案しない。脆弱性検査のワークフローを追加し、`pip-audit` でボットと管理コンソールの requirements を Windows／Linux・Python 3.11／3.13 で推移依存まで解決して照合し、`npm audit --omit=dev` で画面の依存を照合する。依存の定義ファイルの変更時と毎週実行し、権限は読み取りだけでシークレットを使わない。検出は警告の注釈とジョブの概要に出すだけで、誤検知を確かめてから必須にする。`pip-audit` は CI 専用で `.github/audit/requirements.txt` に固定し、ボットの依存には加えない。`SECURITY.md` に依存の脆弱性の確認の担当と頻度を追記した。`discord.py[voice]` が入れる PyNaCl 1.5.0 の CVE-2025-69277 は、ボットが影響する Ed25519 の関数を使っていない（音声の暗号化・復号の AEAD だけ）ことを確かめたうえで、理由と外す条件を残して検査から除外した。discord.py が PyNaCl 1.6 系を許す版を出したら更新して除外を外す。依存のバージョン更新は含まない（#285）。
- **推移依存の固定（constraints.txt）**: これまで直接依存だけを固定し、推移依存（47件）はインストールした時点の最新版になっていた（公開当日の版が入ることもあった）。`constraints.txt` で推移依存の版を固定し、`requirements.txt` の `-c constraints.txt` から読むため、手順書・CI・管理コンソールのデプロイの `pip install -r requirements.txt` はそのまま使える。作り直しは手動で実行するワークフロー（Windows／Linux・Python 3.11／3.12／3.13）で行い、直接依存は `requirements.txt` の版のまま、推移依存は pip の `--uploaded-prior-to` で公開から14日以上たった版だけから選ぶ。上限内の版に既知の脆弱性があるときは、修正版を `.github/constraints/security-exceptions.txt` に理由と外す条件付きで書いて例外にする（導入時に、上限内の certifi 2026.7.22 が CRITICAL の GHSA-6q48-6c7w-9gw2 に当たったため、修正版 2026.10.19 を例外にした）。環境で版が分かれる依存（contourpy は Python 3.12 以上で 1.4.0）は環境マーカーで書き分ける。Dependabot は推移依存の更新を1つの PR にまとめ、書き分けた依存は提案せず作り直しで更新する。管理コンソールのデプロイは `constraints.txt` だけの変更でも依存関係を入れ直す。最初の `constraints.txt` は手元の Windows（Python 3.11／3.13、3.12 は 3.11 からの解決）で作り、Linux と Python 3.12 でも全件が固定版で入ることを確かめた（#285）。
- **Dependabot の依存更新の取り込み**: 毎週の提案のうち、公開から14日以上たった版を取り込んだ。ボットは matplotlib 3.10.8 → 3.11.2、管理コンソールのバックエンドは FastAPI 0.142.2 → 0.146.0 と asyncssh 2.24.0 → 2.24.1、画面は react 19.3.1・react-dom 19.3.1（版をそろえて固定）・material-symbols 0.48.0・@fontsource-variable/noto-sans-jp 5.3.1、CI は actions/setup-node 7.1.0・upload-artifact 7.0.2・download-artifact 8.0.2。TypeScript 7・@vitejs/plugin-react 6 などの大きな更新と、推移依存の更新（`constraints.txt` は作り直しで更新する）・PyNaCl 1.6.2 の提案は取り込んでいない。
- **運用ログの段階的移行（第4段階）**: audio・設定読込・共通処理のprintをloggingへ移行。会話・添付名・応答本文・設定値・ファイルパスを既定ログから外し、会話件数とトークン数の集計形式を維持する。音声の代替・再生・キャンセル、ファイル保存や復旧の動作は保ち、設定不足時のキー名と対処案内は単独実行でも表示する（#283）。
- **運用ログの段階的移行（第3段階）**: views のログを固定文と診断用の例外情報へ整理。通常パネルと中止ボタンの想定外エラーも、View・Item・操作内容のreprを出さずに記録する。返信文・権限判定・所有者管理・キャンセル・グラフバッファの回収は維持する（#283）。
- **運用ログの段階的移行（第2段階）**: services のログをloggingへ移し、モデレーション理由・NG語・会話断片・日時入力・利用者や配信先の識別情報・例外本文を既定ログから外す。記憶圧縮は事前整形した例外文字列を受け渡さず、元例外を診断情報として保持する。判定結果・利用者への返信・保存データ・再試行やキャンセルの動作は維持する（#283）。
- **運用ログの段階的移行（第1段階）**: 起動処理と `core/` のログを時刻・レベル・モジュール名付きの標準出力へ統一。識別子・例外本文・非公開NG語を既定ログから外し、管理コンソールは旧printと新loggingの集計・伏せ字に両対応する。後続のservices・views・audio等は別の変更単位で移行する（#283）。
- **保存データの配置整理**: ルート直下の `memory/`・`ng/` を `data/memory/`・`data/ng/` へまとめ、ボット・管理コンソール・Gitの除外設定を新配置へ統一。既存環境向けにバックアップと内容照合を行う移行スクリプトを追加し、旧配置が残る場合は空のDBを作らず起動を止めて移行を案内する。`prompts/`・`.env` と起動方法は従来どおり。
- **記念日のプロフィール検索用索引**: スキーマ14への移行で`profile(key, user_id)`の索引を追加し、記念日巡回が無関係なプロフィール行を全件走査する処理を避ける。ユーザー別の記憶取得・保存・圧縮は従来の主キーと仕様を保つ（#249）。
- **UI タスクの所有者管理**: discord.py 標準の `View._dispatch_item` は `asyncio.create_task` で直接タスクを作るため、ボット終了時に所有者の回収待機へ含まれない問題を解消。`PanelView` 基底クラスで `_dispatch_item` をオーバーライドし、全パネル（キャラ設定・会話要約・会話統計・自発会話・リマインダー・統計プライバシー・ブロック解除・ヘルプ）に適用。`interaction_check` に `stopping` チェックを追加し、終了後の UI 操作を早期に拒否。
