# ver0.2.0(BETA)

## 新機能

- **紹介用ホームページを追加する**: 何ができるボットかを一般の利用者に向けて紹介する 1 ページのサイトを `Site/` に追加した（React + TypeScript + Vite。GitHub Pages で公開する）。キャッチコピー、疑似的な Discord 画面で見せる動作イメージ（会話・記憶・リマインダー・音声会話・自律配信・サブエージェントの 6 場面。登場人物と会話は架空）、機能紹介、制作背景と目的、使い方、技術スタックと使用しているツール、更新履歴への入口、免責事項で構成する。配色は紹介動画の暗い地とティールを土台にしたライト／ダーク両対応。ボットの招待 URL・紹介動画・アクセスの計測は載せず、外部のスクリプトやフォントも読み込まない。依存は管理コンソールと同じ版だけを使い、ボット本体の依存とコード（`src/`）は変えていない。公開は `.github/workflows/site.yml` が行い、リポジトリの変数 `SITE_DEPLOY_ENABLED` を `true` にするまでは動かない（手順は `Site/README.md`）（#410）。

- **音声会話でボットの発話中に割り込めるようにする（エコー除去によるバージイン）**: ボットが話している間も参加者の声を聞き続け、再生した声を参照信号にして受信した音声から回り込み（エコー）を取り除く。エコー除去は numpy だけで実装し（遅延の推定は GCC-PHAT、除去は周波数領域の分割ブロック適応フィルタ、残りのエコーはコヒーレンスと除去量で見分ける）、受信のスレッドで処理して会話を遅らせない。ボットの声が出ている間の話し始めはすぐには送らず、2 秒以上話し続けたら Gemini Live へ送り、文字起こしが言いよどみ・相槌以外の複数の語になったら割り込みと確定して、ボットの声を強めにフェードアウトさせる。相槌では止めず、言いよどみだけで遮った形になったときはボットが続けてよいか確認する。文字起こしがボット自身の直前の発話とほとんど同じなら回り込みとみなし、その発言への返事を再生しない（音声ループの防止）。会話の終了・違反の検出では即座に止める。しきい値は合成した音声で決めた初期値（`LIVE_AEC_*`・`LIVE_BARGE_IN_*`・`LIVE_ECHO_*`）で、実際の通話での調整に使えるよう、終了時に割り込みの判定件数と推定した遅延・除去量をログへ出す（本文・話者は出さない）（#409）。

- **サブエージェントの作業スレッドを完了時に閉じる**: 作業が完了し、ペルソナが元のチャンネルへ結果を返信したら、作業スレッドをアーカイブする（ロックはしない）。失敗・中止・時間切れのスレッドは閉じずに残す。閉じられなかったときは、理由を元のチャンネルへ定型文で知らせてスレッドを残す。閉じたスレッドへの書き込みで再開したときは、追加の依頼があるかを 1 回だけ尋ね、スレッドの中で頼んだ追加の作業も完了したら閉じ直す。自動アーカイブの時間の指定（`AGENT_THREAD_AUTO_ARCHIVE_MINUTES`）はやめ、チャンネルの既定に任せる。`personas.json` の `agent` に `archive_failed`・`reopened` の文面を追加した（#408）。

## その他の変更

- **紹介用ホームページの動きを増やす**: ファーストビューの見出し・説明・ボタン・動作イメージが読み込み時に上から順に現れ、背景の光がゆっくり揺れるようにした。動作イメージのタブは選択中の背景がタブからタブへ滑って移り（幅の狭い画面では選ばれたタブが見える位置まで横に送る）、場面が替わるとチャンネル名と説明がふわっと入れ替わる。ほかに、見出しの飾り線が伸びる動き、機能カードのアイコンの hover、スクロール時のヘッダーの影、配色ボタンのアイコンの切り替えを足した。どれも跳ねない動きで、端末の「動きを減らす」設定では止まる（順番に出す要素の遅れも消す）。依存は足していない。
- **音声会話・自律行動の責務分割とキャラ設定パネル・followup ボタンの共通化**: `voice_conversation.py`（1,596 行）から、状態（同意・参加者・発言・話者の管理・文字起こしの帰属）を `voice_conversation_state.py`、同意の付与・撤回と同意パネルの更新を `voice_conversation_consent.py`、入出力のモデレーション・違反記録・記憶と親密度への反映を `voice_conversation_moderation.py` へ分け、状態の読み書きは `_state_property` による橋渡しをやめて `_speaker_state` / `_transcript_state` を直接通す。`autonomous_service.py` からは、第一声・独り言・コメント応答の生成・検閲・投稿・読み上げを `autonomous_speech.py` へ分けた。公開クラス・メソッド・ログの出元（ロガー名）は変えていない。キャラ設定パネルの組み立て（ペルソナ一覧の読み直し・違反件数をボット所有者だけへ見せる判定・管理者判定）はハブと配信先パネルから戻る経路で `build_settings_view` に共通化し、ハブ側も応答の保留後に最新の Member で管理者を判定する。パネルを残して followup を返すボタンの二重実行の防止は `StatsView` から `PanelView`（`try_begin_aggregation` / `end_aggregation`）へ引き上げ、📊 グラフ・🔄 NGワード再読込にも適用して、実行中に押し直すと「処理中です」と案内する（#415）。
- **ボイスコマンド・旧データ取り込み・定期ループ・ペルソナ検証の整理**: `commands.py` から `/join`・`/leave` の接続処理を `voice_commands.py` の `VoiceSessionCommands` へ移し、`register_commands` はコマンドの登録と共通の入口に専念させた。`database.py` の旧データ取り込み（移行・ファイル取り込み・`profile.json` の吸収）を `db_legacy_importers.py` の `LegacyDataImporter` へ移し、guild_settings・記念日の投稿記録の全件読込の変換を共通化した。`bot.py` の 6 つの見回りループの生成と `on_ready` の起動は共通のヘルパーと `BotState.start_background_once` にまとめ、`personas.json` の再読込と項目の検証（オブジェクトの判定・未対応の項目の検出）を共通化した。動作は変えていない。ボイス接続のログの出元は `persona_bot.core.voice_commands` になり、`personas.json` の未対応の項目の警告は、複数あっても 1 回にまとまる（#414）。
- **遠隔集計の起動と状態の分離**: 管理コンソールのインサイト・DBテーブル読取を、実行ごとの状態を持つ収集関数とCLI入口へ分けた。標準入力で送る従来の実行方法を保ち、モジュールの読込だけでは設定・DB・外部通信へ触れず直接テストできる（#396）。
- **終了・受付枠・DBロック待機の防御**: サービス終了通知の所有者と期限超過の検査を明示し、Taskを伴わないコルーチンの実行も追跡する。未確保の会話枠の返却を無視し、SQLiteのロック待機上限を30秒へ明示した（#397）。
- **評価の一括削除への追従**: 👍👎 の片方をまとめて削除した場合は残った側へ評価を戻し、全リアクションを削除した場合は評価記録を取り消す。保存中に次の評価操作が届いても、最後の状態を残す（#391）。
- **会話要約の対象件数**: 本文の行数ではなく、要約へ採用したメッセージの数を表示・利用履歴に記録する。複数行の投稿は1件とし、除外した投稿は数えない（#392）。
- **接続設定の文字コード案内**: 管理コンソールの接続設定がUTF-8として読めない場合も、画面へ設定エラーを返し、UTF-8（BOM付きも可）での保存を案内する（#393）。
- **プロジェクト名の変更**: プロジェクト名を Persona Agent for Discord に変更し、リポジトリの URL と各種ドキュメントを新しい名前に合わせた。既存環境のフォルダ名を変更する必要はない。
- **テスト補助・ログ・型ヒントの整理**: Discord の架空の Interaction・Message・Channel・Guild を作るテスト用ファクトリを共通化し、日時ユーティリティの単体テストを追加した。プレースホルダーのない f 文字列と未使用の変数を除き、JSON 保存のログには壊れたファイルの名前（内部の固定ファイルのみ。絶対パスと退避先の名前は出さない）を出す。グラフ描画の型ヒントを補った（#378）。
- **メッセージ処理の境界の明示**: 受付・振り分け・応答の各段へ、メッセージ処理のモジュール全体ではなく、型付きの外部操作（履歴取得・返信・読み上げ・画像取得・ペルソナ読込・背景タスク）だけを渡す。足りない操作は起動時に分かり、各段の未定義の名前もテストで見つける。動作は変えていない（#395）。
- **テスト用モックの横断適用とデータベース層の分離**: `tests/views/` に残っていた手書きの Interaction・応答・HTTP エラー応答の代役を共通ファクトリ（`make_interaction`・`make_response`・新設の `make_http_response`）へ移し、チャンネルの履歴取得を模す `make_history`（`make_channel(history_messages=...)`）を追加した。`database.py` からスキーマの定義と適用を `db_migrations.py`、旧 JSON・テキストの読み取りと解釈を `db_legacy_importers.py` へ分け、`Database` は従来のメソッドを保ったまま窓口として委譲する（管理コンソールが読む `SCHEMA_VERSION` は `database.py` に残す）。会話履歴の添付表記は、画像以外の添付があるときだけ付ける条件を `any(...)` で明示した。動作は変えていない（#400）。
- **更新履歴の置き場所と README の整理**: README の半分を占めていた更新履歴を、版ごとのファイル（`docs/release-notes/verX.Y.Z.md`。一覧は `docs/release-notes/README.md`）へ移した。GitHub の Release の本文にも同じファイルを使う。管理コンソールが表示する配備中の版は、番号が最大のファイルの見出しから読む（このフォルダが無い旧版のサーバーでは従来どおり README から読む）。あわせて README の説明を要点に絞り、ディレクトリ構成を実際のファイルに合わせ（`.github/`・`AGENTS.md`・`CONTRIBUTING.md` などを追加し、DB のテーブル数を更新）、ライセンスへのリンク切れ（`LICENSE` → `LICENSE.md`）を直した。
- **フロー図の更新とアクティビティ図の追加**: `docs/フロー図.drawio` を現在のコードに合わせた。A-1 は 15 のサービス（`AgentService` を追加）・データ配置の確認・スキーマ版 15 と 10 テーブル・`on_guild_remove`・エコー除去を反映し、A-2 はメッセージ処理の 3 段（受付・振り分け・応答）と「通常チャットは読み上げない」を明記した。B-1 はコードの順序に合わせてチャンネル種別の判定をブロック判定の直後へ移し、作業スレッドの再開の確認（#408）・委任の分岐・文書キューの上限（#202）を加え、配信コメントの応答だけを読み上げへつないだ。B-2 は発話が `autonomous_speech.py` へ分かれたことを反映した。新たに UML のアクティビティ図を 3 ページ追加した（C-1 `/join` から音声会話の開始まで、C-2 音声会話の 1 ターン、C-3 サブエージェントへの委任）。コードは変えていない。

## 不具合修正

- **紹介サイトの動作イメージと管理コンソールの伏せ字**: 動作イメージのボイス・ステージの参加者は、今までに発言の見えた人だけを表示し、途中参加の人はその発言が出たときに加わる。視差効果の設定を切り替えたときは、そこまで進めた経過時間の表示へ組み直し、全件表示で固まったり再生中に急に巻き戻したりしない。ページを開いた直後（`<StrictMode>` の初回マウントを含む）と視差効果の切り替えでは、場面のタブを横へ送らない。管理コンソールの伏せ字モードは、既定の `bot` 以外の systemd のサービス名と、概要のボット欄のヒント（配備先ディレクトリを含む文）も伏せる。サーバー名が取れなかったときの代替表示（「名前不明のサーバー」「保存済みサーバー N」）を秘密とみなさず、前後の空白のあるサーバー名でも頭文字をアバターに出す。紹介サイトのテストに、`blob/main` のリンク先のファイルがリポジトリに実在することの回帰を追加した（#452）。
- **管理コンソールの例外件数・伏せ字・デプロイ異常時の状態**: 概要の「例外（24時間）」は、現行のボットが出す `例外: <型名>` の行（従来の `Traceback` と合わせて）を数える。概要・操作・データの各画面のエラー文とサービス名・説明にも伏せ字を適用し、起動確認の `ログイン成功: <ボット名>` は、ボット名が未取得や短くても構造で隠す。デプロイで想定外の例外が起きたときは、実行中のステップを失敗・未実行のステップを見送りに揃え、例外の本文は画面に出さず固定の案内にする（型名はコンソールのログへ）。起動確認中にボットが落ちて別のプロセスで再起動済みだった場合も、失敗の前に直近のログを添える。ボイス状態の取得は応答の型と `channel_id` の形式を確かめ、1つのサーバーの異常で全サーバーの一覧を失わない（#433）。
- **管理コンソールのログAPI・遠隔集計・サーバー画面**: `GET /api/logs` の `lines` が1〜1000の範囲外なら、遠隔コマンドを送らず 422 で拒否する。`db_summary` は `Path` を渡しても動き、`main(argv)` の入口を持つ。`db_table` は開始位置・件数に `None`・真偽値・数値でない型が渡されても既定値へ戻す。サーバー画面はペルソナ名と注記も伏せ字の対象にし、空のサーバー名は代替の表示にする（#413）。
- **管理コンソールの切断時の伏せ字とAPIの検証**: SSH 接続が外から切れた場合、伏せ字モードでは切断理由（接続先のホスト名・IP アドレスなどを含みうる）を出さず、定型文を表示する。DB テーブルの API は範囲外の `offset`・`limit` を 422 で拒否する。運用ログの整形は、不正な例外情報を渡されても失敗しない（#399）。
- **旧データの退避ファイル**: 旧 JSON・テキストの取り込み後に作る `.imported.bak` が既にある場合は上書きせず、`.imported.1.bak` のように連番の名前へ退避する。空きがなければ取り込まずに元のファイルを残す（#379）。
- **記憶圧縮の巡回順**: 先頭のユーザーが失敗し続けても後続が見送られ続けないよう、前回の続きのユーザーから巡回する。連続失敗の上限は維持し、全体障害時の1回あたりの試行数は増やさない（#380）。
- **管理コンソールの範囲外の日時**: DB テーブルの日時の列に JavaScript の Date で表せない値（極端に大きい UNIX 秒など）があっても、その値をそのまま表示し、同じページのほかの行の表示を止めない（#394）。
- **サーバー設定の権限と集計ボタン**: 🔍 Google検索の切り替えと 💬 自発会話（自律行動を含む）の確定を、サーバーでは管理者のみに限る（DMは従来どおり本人が操作できる）。画像と検索ツールの併用を断られた場合も、検索なしで画像ごと答える。会話統計の全体比較・フィードバックの集計を、実行中に押し直しても重ねない。リマインダーの登録時の日時の解釈を、繰り返しの次回時刻と同じ夏時間の規則にそろえる（#398）。
- **音声会話の割り込み・終了、パネルの戻る、サブエージェント、記念日**: 返答の最初の音声が届く前に別の人が割り込んでも、前の人宛ての遅れた返答を新しい発言への返答として流さない。音声会話の停止は同意パネルの更新を待ってから終了表示にし、未接続で再生を始められなかったときや再生が途絶えた直後のチャンクも状態を残さず再生し直す。「↩️ 戻る」で遷移を取りやめたときは生成済みの親パネルを止める。サブエージェントの作業スレッドは Webhook の再取得にボット自身の ID を使い、中止と作業完了が同時に起きたら中止を優先する。記念日のお祝いはブラックリスト登録者を対象外にし、数値でない ID を静かに読み飛ばす（#412）。
- **ステージの `/join`・音声会話の後始末・パネル操作・トークン記録**: ステージでは、ボットを発言者へ昇格できてから音声会話と同意パネルを始め、昇格できなければ観客のまま同時枠を占有せずに退出して案内する。音声会話は、破棄した発言の文字起こしの帰属待ちで次の話者の発言が記憶から外れないよう、破棄と同時に閉じる。同意を撤回して文脈を張り替えるときは、別の人の発話とボットの再生も直ちに止め、ボット自身が別のチャンネルへ移された瞬間にも見回りを待たずに会話を一時停止する。再生スレッドの待機がキャンセルされても残りを待ち終えてから伝え、切断した話者の音声デコーダは回収し、停止の直後にデコーダを入れ直さない。ブロック解除・統計プライバシーの確定・リマインダーの取り消しは、閉じた・別の画面へ移ったパネルの操作では実行しない。自発的な会話・記念日・会話要約・文書の応答は、生成に成功した時点で消費トークンを記録し、後段で却下しても統計から欠けない。`personas.json` の未登録の `eq` は読み込み時に警告し、空の `live_voice` は警告なしの「既定の声」として扱う。参考リンクは改行や `>`・空白を含んでも1行のリンクに保つ（#432）。

- **保存と管理コンソールの境界処理**: JSON保存先の未作成フォルダを作成し、属性の不足したチャンネルも表示する。SSH終了確認のキャンセル時も履歴を残し、タイムゾーンの非公開情報をログへ出さない仕様を明確化する。ログストリームの取得行数を1〜1000行で検証する（#376）。
- **再生制御と処理の責務整理**: TTSとLiveの再生排他・スレッド待機を共通化し、メッセージの受付・振り分け・応答を分離する。設定保存のスキーマ検証をキャッシュし、整形済み履歴の無害化の重複を省く。サーバーのキャラ設定確定を管理者に限定し、確定直前の権限確認を共通化する（#377）。

- **終了処理とDB初期化**: サービスへの終了通知を先に行い、停止中に生成したタスクも回収する。終了待ちに上限を設け、超過時は失敗を報告して使用中の共有リソースを保護する。DB初期化の単一トランザクションと失敗時の巻き戻しをテストする（#374）。
- **音声・代替生成・記憶圧縮**: 再生スレッドの終了を待ち、音声の端数フレームを次の入力へ保持する。同じ発話の遅延二重記録、検索クォータ例外の判定漏れ、有効な行IDを持たない記憶ログの再生成と失敗回数リセットを防ぐ（#375）。

- **ログと音声参加**: 切断直前に受信したログを表示し、`/join` の待機中に依頼者が移動または退出した場合は接続を中止する（#372、#373）。

- **記念日と管理コンソール**: 記念日の投稿記録を保存中にサーバーへ再参加しても、保存完了後に復元する。深くネストした JSON がある場合も DB の他の行を表示する（#370、#371）。

- **違反通知と検索・生成処理の整理**: テキストと音声の違反記録、検索出典、JSON 応答の共通処理をまとめ、サブエージェントの実行処理を分離する（#365）。
- **管理コンソールの保守性**: systemd ジョブの終了確認と確認ダイアログの構築を分離し、ボットの設定選択肢を AST で検証する（#366）。

- **管理コンソールのデプロイと操作**: 中断後に取り込み結果を照合し、巻き戻しを一度だけ完了させる。起動直後の異常終了を検出し、SSH 切断時の状態取得、ログ再開とモーダル操作を修正する（#363）。
- **パネルと復元処理の整理**: 一時選択と分割結果の表示を共通化し、会話要約をサービスへ分離する。起動時のサーバー設定・記念日記録をまとめて読み込み、音声の補間比を検証する（#364）。

- **サーバー退出と設定パネル**: 退出処理の開始時から古い設定とパネルを無効にし、設定画面への復帰時に権限とブラックリスト件数を更新する。失効した操作による一時選択・会話リセットの変更とグラフ送信時の内部エラー露出を防ぐ（#361）。
- **音声会話と自律配信**: 同意撤回後の応答破棄、発話予約の期限、接続失敗時の回収、配信コメントの検査と停止処理を修正する。統計の並行解析、文書処理とリマインダーの境界条件も修正する（#361、#362）。

- **管理コンソールの内部整理**: 接続状態の取得・ショートカット・ログ表示を分離し、キャンセル時の待機と接続世代の確認を共通化する。ボット本体のキュー・リマインダー状態と表示定義の整合性をテストする（#353）。
- **文書要約の使用量**: 要約で消費したトークンを利用履歴に記録する。要約本文やファイル名はログへ出さず、会話件数にも加算しない（#352）。
- **音声と自動投稿の内部整理**: 発話の順番待ち・文字起こしの帰属を分離し、音声の権限確認と自発投稿・自律行動の共通処理を整理する（#352）。
- **管理コンソールの接続とデプロイ**: 文書の送信中を表示し、未作成の設定テーブルによる誤警告を防ぐ。ログ取得中の接続切替を検知し、終了時はサービス操作の完了を待つ。デプロイの時刻取得失敗を検知し、再起動後の巻き戻し前に systemd ジョブの終了を確認する（#350）。
- **ブロック解除パネル**: 一覧が Discord の選択肢上限を超えるとき、先頭の25件を表示していることを案内する（#351）。
- **パネルと設定の保守性**: パネル操作の権限再確認と応答検査を共通化し、ボット終了時の操作管理を discord.py の既存処理に委ねる。サーバー設定の保存列・属性・既定値を集約し、DB の列と食い違う場合は保存を拒否して既存設定を保護する（#351）。
- **統計・要約パネルと設定画面の復帰**: 実行開始の画面更新中に別の操作が重なっても処理が停止せず、統計本文の表示後に続きや画像を送れなくても表示済み本文を残す。配信先設定から戻る際は、ペルソナ一覧・NGワード件数を更新し、確定前の選択を引き継ぐ（#348）。
- **作業スレッドのWebhook復旧**: キャッシュ済みWebhookが削除されていた場合、1回だけ再取得・再送を試み、進捗や最終報告の欠落を防ぐ（#348）。
- **自動投稿・記憶圧縮・統計表示の整合性**: 自律配信中のお祝いを見送り、配信後に再試行する。記憶圧縮ログの消去中にキャンセルされても失敗回数をリセットし、統計収集停止中の未解析状態は解析失敗と区別して案内する。取消済みリマインダーでアーカイブ済みスレッドを再開しない（#349）。
- **退出処理と再参加の競合**: 停止待機中に再参加した場合、古い退出処理から新しい設定・音声会話・接続保護・ウェルカム記録を保護する。モデレーション差し替え後の返信には検索リンクのプレビュー抑制を適用せず、TTSのタイムアウトログの不要な識別子表記も除く（#349）。
- **音声会話の開始失敗・停止時の後片付け**: 設定読込や音声会話開始の失敗・中断、既存接続の再利用時の上限到達でも、予約枠と会話できない接続を残さない。会話の置換中も枠を保持し、開始待ち中の退出後に古い処理が会話を復活させたり、新しい予約を解放したりしない（#346）。
- **音声会話の再接続と受信の安定化**: 再接続時に検索の利用枠を超えた場合、同じ試行内で検索なしの接続を直ちに試す。終了・差し替え済みセッションの受信ループ、不正なRTP拡張長・パディング、話者の再参加・割当変更・再接続後に残る古いデコーダ状態を修正する（#347）。
- **接続切替時のテーブル閲覧**: 管理コンソールで接続先を切り替えた直後に、前の接続で選んでいたテーブルの中身を自動取得しない。新しい接続で明示的に選択するまで取得を止め、選択後のページング・行の展開・伏せ字は維持する（#344）。
- **音声会話の再開時の接続保護**: Live終了案内の送信待ち中に新しい音声会話を開始した場合や開始枠を予約した場合は、旧会話の終了処理で接続保護を解除・切断しない（#345）。
- **再参加後の設定保護**: サーバー退出前に開いた設定パネルを無効にし、開き直しを案内する。操作や保存の待機中に退出した場合も、再参加後の設定を古い値で上書きしない（#342）。
- **デプロイ対象の取得**: single-branch cloneなどで対象ブランチが追跡範囲外でも、最新コミットを取得して更新の有無を正しく判定する。更新なし・サーバーだけのコミットがある場合の判定は維持する（#343）。
- **統計収集設定の保存失敗の案内**: 収集の停止・再開を保存できなかった場合は、成功文を表示せず、設定が変更されていないことと再試行の手順を案内する。表示と実際の収集状態の食い違いを防ぐ（#340）。
- **リマインダーのDB障害と再試行**: 一覧取得・取消のDB障害を「予定なし」「通知済み・取消済み」と区別して案内する。失敗時も操作パネルを残し、一覧の再取得や取消の再試行を可能にする（#341）。
- **管理コンソールのデプロイ巻き戻し**: 巻き戻しの直前にブランチ・HEAD・追跡ファイルの変更を確かめ、デプロイ中にサーバーで編集・ブランチ切替・想定外のコミットがあれば、何も変更せずに中止して安全な復旧手順を案内する。戻す操作は `git reset --hard` ではなく `git reset --keep` にし、確認後の編集とも衝突すれば git が中止する（#381）。
- **`/join` の接続切替・長文分割・退出時の設定読込・DB行の変換**: 接続先を切り替えるときは `/leave` と同じ順序で先に接続保護を解き、音声会話の停止を待つ間に実行者が離脱しても、既存の接続を必ず切断する。長文の分割は、制限文字数の直後にある改行・空白も区切りとして使う。サーバー退出時は無効にした設定の読込を残さず、新しい読込要求が失敗しない。統計の収集停止設定が `null` で保存されていても、旧キーと既定値へ順に落として停止を保ち、親密度の最終会話時刻は数値に正規化する（#411）。
