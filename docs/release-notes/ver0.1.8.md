# ver0.1.8 — 2026/10/25

## 新機能

- **サブエージェント**: 会話の中で「サブエージェントを使って」と明記した依頼を、ペルソナから別の AI（サブエージェント）へ委任。委任するか・子に与える役割・依頼内容・期待する出力形式・手順は、モデレーション・記憶カテゴリ・リマインダーと同じ 1 回の判定（`check_and_route`）でまとめて決め、調べ物が要らない内容はペルソナがその旨を添えてそのまま回答。子は独立した文脈で Google 検索つきの手順を最大 3 回行って Markdown で報告し、返信は常にペルソナが報告を自分の口調で言い直して行う（参考リンクつき）。作業中は AI を使わない定型文の進捗メッセージ（`personas.json` の `agent` でキャラごとに変更可）と、依頼した本人だけが押せる中止ボタンを表示。失敗・時間切れ（5 分）も定型文で伝え、同じ人の依頼は 1 件ずつ・全体で同時に 2 件まで
- **ボイス接続先の保護**: 管理者などがボットを別のボイスチャンネルへ移したとき、`/join`の接続は元のチャンネルへ戻り、自律行動の配信は締めの一言を残して移動先から退出。元のチャンネルの削除・権限不足・復帰失敗・短時間の連続移動では戻らずに退出し、自動で入り直さない。移動の瞬間に再生中だった読み上げは止め、`/join`・`/leave`・配信の開始と終了は移動と区別
- **自作のペルソナ**: キャラ別のプロンプトの同梱をやめ、書式見本`prompts/00_prompt_format.txt`と、`personas.json`の書式見本`prompts/00_prompt_format.json`だけを公開。`prompts/`に置いた`.txt`がキャラ設定の選択肢になり、パネルを開くたびに読み直すため再起動は不要。表示名・読み上げの声・既定のペルソナは任意の`prompts/personas.json`（JSONの見本をコピーして作る）で設定。ペルソナが1つも無い間は標準のプロンプトで応答し、パネルで作り方を案内。選んだファイルが見つからない間も選択は保ち、既定のペルソナで応答。キャラ別のファイルと`personas.json`はGitの管理対象外にし、作り方・SCP/SFTPでのサーバーへの転送・既存環境の更新手順（更新前の退避と復元）をREADMEに記載。管理コンソールの表示名も`personas.json`から取得

## 運用・構成の整備

- **Python 3.11 以上が必須に**: Pillow に出ていた Dependabot のセキュリティ警告（critical・high・medium）の修正版 13.0.0 が Python 3.11 以上を必須とするため、対応する最小の Python を 3.10 から 3.11 へ変更。CI と各ガイドの対象版を 3.11／3.13 に更新し、あわせて pypdf を 6.21.2、管理コンソールの vite を 7.3.7 へ更新して該当の警告を解消。**Python 3.10 で動かしている環境（サーバーを含む）は、更新前に Python 3.11 以上へ入れ替えて `pip install -r requirements.txt` を実行すること**（3.10 のままでは Pillow 13.0.0 を導入できない）
- **管理コンソールの起動ブラウザ**: Windowsの専用画面を、Microsoft Edgeが入っていてもGoogle Chromeで開くように変更。Chromeは全てのインストール先を探し、見つからない場合だけ従来どおりEdgeで開く。専用プロファイルはブラウザごとに分け、Chromeでの初回は画面の設定が既定値から始まる

## 不具合修正

- **BOM付きの旧設定の移行**: 旧`config_private.py`・`config.py`を「UTF-8 (BOM 付き)」で保存していると、Pythonとして正しいファイルでも移行スクリプト（`deploy/migrate_config_to_env.py`）が構文エラーと判定し、キー未設定で`.env`を作れない問題を修正。BOMの有無にかかわらず同じ内容として読み、旧ファイルを実行せずトップレベルの文字列代入だけを読む動作と、値をログへ出さない動作は維持
- **文書処理の失敗通知**: 文書処理に失敗したとき、内部の例外の本文（ファイルの場所など）がそのまま元の投稿への返信に載り、公開チャンネルへ出る問題を修正。返信は定型文にし、サイズ超過・暗号化PDF・UTF-8で読めないテキスト・対応する添付なしのように利用者が対処できる場合だけ理由を添える。原因の詳細はログと失敗記録にだけ残す
- **文書返信の中断**: 送信開始の記録中にキャンセルすると、未送信の文書が再開されなくなる問題を修正。記録開始から返信・完了保存までを中断から保護し、保護前の中断は次回起動時に再開
- **スラッシュコマンドの終了**: 応答待ちのコマンドがボット終了後に接続や保存へ進む問題を修正。実行中の本体と後片付けを回収してから共有接続を閉じ、停止後の新規実行も抑止
- **ボイス参加・退出の競合**: 応答や自律配信の停止を待つ参加コマンドが、後から実行した退出の後に接続する問題を修正。同じサーバーの接続変更を直列化し、後続の操作より古い参加は見送り
- **文書の受付後の編集**: 文書を受け付けた後に投稿の本文を編集すると、NG判定と入力のモデレーションを通っていない本文で回答が生成される問題を修正。受付時に確認した質問で回答
- **文書の受付上限**: 処理待ちの文書を1人3件・全体20件までに制限し、超えた分は受け付けずに案内するよう修正。1人の大量投稿で他の利用者の文書が待たされ続けることを防ぎ、回答や失敗で処理が終われば再び受け付け
- **返信のメンション通知**: 通常会話・文書・自律配信コメントへの返信で、AIの本文に`@everyone`・`@here`・ロール・他の利用者へのメンションが含まれていても通知しないよう修正。分割した2通目以降も同じ扱いにし、返信先の本人への通知は維持
- **記憶圧縮の記念日**: 圧縮結果で記念日が省略されたり形式が壊れたりすると、登録済みの誕生日・記念日が消える問題を修正。既存の記念日をラベル単位で保持し、正しい日付訂正と新しい記念日は反映
- **長文の分割・送信**: 境界付近に空白・改行だけの断片ができても送信しないよう修正。中身のある断片の字下げと改行、最初の返信を返す動作を維持し、統計・会話要約の本文が空でも適切に案内
- **自律配信の権限変更**: 配信中の閲覧・送信・発言権限の喪失と、ステージで観客へ戻されたことを毎分の見回りで確認し、独り言を生成する前に停止。送信権限が無い場合は締めの投稿を省き、開始時だけ必要な管理権限の喪失では配信を維持
- **記憶圧縮と文書返信**: 他の利用者の発言で圧縮待ちが延びないよう利用者別に判定し、空の投稿者IDを拒否。複数添付の要約をまとめて保存し、同名・同内容の再処理では重複を除去。文書返信は送信と完了記録を中断から保護し、強制終了で送信結果が不明な場合は自動再送を止める
- **配信・読み上げ・自動通知**: 第一声や独り言の送信失敗時に配信を停止し、時差情報のない日時でもゲージを計算。閉じていないコードブロックを読み上げず、記念日は本人が閲覧できるチャンネルへ投稿。アーカイブ済みスレッドのリマインダーは元のスレッドを再開して通知
- **管理コンソール**: 接続切替で古いサービス操作の確認を無効にし、形式の壊れたログでも受信済みの行とエラーを保持。デプロイ先ブランチと操作履歴の接続先IDにも伏せ字を適用し、日別評価の期間条件を整理
- **管理コンソールの伏せ字**: ログの取得境界や区切り線で会話の本文が公開に戻る問題と、接続先・Gitブランチ・デプロイ手順・確認ダイアログに原文が残る問題を修正。ログは受信時に会話・不明を判定して保持し、伏せ字中はsystemd以外のログ本文を通常運用も含めて隠す（本文と運用を確実に区別できないため）。デプロイのログ混在出力も全体を隠し、確認ダイアログは開いた後の伏せ字の切り替えにも追従。ボット本体の出力は変更せず、実ブラウザ・SSH・Discordでの確認は含まない
- **管理コンソールの通知・設定エラー・運用ログの伏せ字**: SSH設定エラー（欠損した鍵・known_hosts）のローカルのパスと、運用ログの過去のチャンネル名・サーバー/チャンネルの識別子が伏せ字中も出る問題を修正。通知は原文を保持して表示のたびに伏せるため、表示済みの通知も伏せ字の切り替えや後から増えた秘密値に追従。伏せ字中は設定エラーを安全な文面（対処方法は残す）へ切り替え、通常表示は従来の診断のまま。運用ログの名前・識別子はエラー文・ツールチップ・ログを含まないデプロイ出力などでも隠し、名前を途中で切らないよう広めに隠すため周りの診断文も伏せることがある（systemd 以外のログ本文は従来どおり全体を隠す）。ボット本体の出力は変更せず、実ブラウザ・SSH・Discordでの確認は含まない
- **評価対象のモデル**: Google検索用のサブモデルが生成した返信も、利用者の選択モデルへ評価される問題を修正。実際に本文を生成したモデルと今回のペルソナで集計し、検索なしへの退避や生成中の設定変更にも対応
- **コマンドとサーバー退出**: スラッシュコマンドの予期しない失敗を、応答保留後も本人だけへ通知。`/join`では「チャンネルを見る」権限も接続変更前に確認し、サーバー退出時は自律配信の停止後に設定・案内済みの記録・ボイス保護の一時状態を解放
- **モデレーションと会話記憶**: 判定APIの空応答を利用者の違反に数えず、明示的な不適切判定とプロンプトブロックは維持。差し替えた謝罪文は通常・文書返信とも会話記憶へ保存せず、親密度は判定通過後だけ更新。違反通知の送信失敗、他のボットのリアクション削除、未ブロック利用者の解除結果も修正
- **設定・リマインダー・会話要約**: 設定確定の応答保留を非公開へ統一し、リマインダーの説明が空でも選択肢を表示できるよう修正。会話要約の全体公開では、分割した投稿も含めメンション通知を無効化
- **読み上げの再生と解放**: 同じ接続の再生・停止を直列化し、再生中・一時停止中の音声を安全に停止。タイムアウト・繰り返しのキャンセル・完了通知の後も、再生スレッドの終了を待ってからPCMバッファを解放
- **旧プロフィールと保存値**: 辞書だけで構成された旧プロフィールをユーザー別形式と誤認する問題を修正。ユーザーIDの形式も確認し、引継ぎ先のない旧データは原本を保持。統計・文書キューの`null`は既定値へ、親密度・感情値は有効範囲へ補正
- **感情タグと保存設定**: 本文中の引用より最後の感情タグを採用し、複合形式の感情タグも読み上げから除去。自発会話の間隔では真偽値・選択肢外を拒否し、統計の日時は末尾`Z`でもPython 3.10で解釈できるよう統一
- **管理コンソールの接続・ログ**: SSH設定エラーで対象ファイルと対処方法を表示。ログ切断後の無限再接続を止め、理由の表示と手動再接続を追加。会話ログの検索結果0件を権限エラーと誤認せず、実際の取得失敗は警告を維持
- **systemdの作業ディレクトリ**: Git管理外の既存ユニットも`src/`へ更新・再配置する確認手順を明記し、旧`index/`による起動失敗を防止
- **旧会話ログの移行**: DBへの取り込み後にバックアップへの改名が失敗しても、再起動時に同じログを二重登録しないよう修正。取り込み済み記録を会話データと同時に保存し、取り込み自体が失敗した場合は原本を保って再試行
- **自律配信のコメント**: 配信コメントから文書処理・リマインダー登録・通常の会話統計が動く問題を修正。本文や読み込める画像が無い投稿は受付枠と独り言の時刻を消費せず、NG判定・入力と応答のモデレーションは維持
- **サブエージェントの中止・期限切れ**: 中止ボタン・全体の期限・呼び出し側のキャンセルで、子の作業の後片付けが終わる前に実行枠が解放される問題を修正。未完了の作業と中止待機を両方回収してから返し、繰り返しのキャンセルも回収後に伝達。中止後に子が報告を返しても成功扱いにせず、期限切れの回収中に中止が押されても期限切れとして扱う
- **収集停止後の統計の閲覧**: 全員が統計収集を停止中だったり、本人だけがデータを持っていて停止中だったりすると、本人が保存済みの統計を開けず「データなし」と表示される問題を修正。本人を初期対象に統計画面を開き、収集の再開や保存内容の変更、Gemini解析なしで停止前の統計と停止中の注記を表示。データが無い場合の案内は従来どおり。管理者の候補・ランキング・他人向けの表示からは、引き続き停止中の人と停止状態を隠す
- **読み上げの再生直前の確認**: 前の再生スレッドの終了待ちや再生ロックの待機中に、ボットが別のチャンネルへ移された・接続が差し替わった・配信が終了した場合でも、移動先で古い返信を読み上げる問題を修正。ロック取得後と前スレッドの終了待ち後に接続・投入時のチャンネル・配信の有効性を再確認し、無効な依頼は現在の音声を止めずに見送り
- **自律配信の停止の共有**: 配信の停止中に`/join`や二重停止が実行されると、停止側が後から参加済みの接続を切断する問題を修正。発話はこれまでどおり直ちに止め、所有する配信枠の削除と切断が終わるまで、後続の停止・`/join`・`/leave`が同じ後片付けを待つよう変更。終了案内は呼出元のキャンセルと一緒に中断でき、後片付けは繰り返しのキャンセルから保護
- **ボイス接続先の保護の退出判定**: 元のチャンネルへ戻る処理の待機中に、同じ接続への`/join`・別の接続への差し替え・同じチャンネルでの保護情報の再登録が行われた場合は、その後に古い移動処理が失敗しても、新しい接続と保護情報を切断・削除しないよう修正。対象の接続と保護情報が両方とも変わっていない場合だけ従来どおり退出
- **自律配信中のボイス参加**: 配信の接続・ステージ準備中に`/join`すると、参加成功後に自律配信の後片付けで切断される問題を修正。開始処理と所有する配信枠・接続の回収が終わってから参加を進める
- **ボイスチャットのNGワード**: メンション必須モードで、ボットが接続中の通話のチャットに書かれたメンション無しの発言がNGワード判定を通らない問題を修正。接続中の通話のチャットに限ってローカルのNG判定だけを行い、違反を記録（AI判定・返信は追加しない）。判定範囲は接続先の移動に追従
- **返信後の読み上げ**: 返信を送った後の会話記憶の保存や評価対象の登録に失敗すると、送信済みの返信が読み上げられない問題を修正。失敗はログに残して送った本文をそのまま読み上げ、保存できなかった会話は記憶圧縮の対象にしない。再生成・再送はせず、返信自体の送信に失敗した場合は従来どおり読み上げない
- **違反記録の保存失敗**: ブラックリストの保存に失敗すると、例外で処理が止まり違反が数えられないまま原因も分かりにくい問題を修正。保存できなかった違反は回数に数えないことを明記し、「あと N 回」の誤った案内を出さずにログへ失敗を記録。記録できた回数とブラックリスト登録もログに出し、NG検出のログと照合できるように
- **BOM付きの記憶ファイル**: 手で直した`projects.json`・`blacklist.json`を「UTF-8 (BOM 付き)」で保存すると、中身が正しくても破損扱いで退避され、プロジェクト記憶や違反記録が空になる問題を修正。BOMの有無にかかわらず同じ内容として読み込み、実際に壊れたファイルは従来どおり原本を退避
- **フィードバックの定期削除**: 新しい評価を選ぶために全件を並べ替えてDBのロックを長く保持する問題を修正。日時とメッセージIDの複合索引を移行で追加し、保持する評価と定期実行の方針を維持
- **フィードバックの両方押し**: 👍👎の両方を付けた人が採用中の方を外すと、残っている評価まで集計から消える問題を修正。最後に付けた方を1票として扱い、片方を外したら残っている側を採用し直す。両方外すと未評価に戻る
- **フィードバックの保存順**: 同じ人の追加・取り消し・押し替えが続いたとき、保存の完了順が入れ替わって取り消した評価が復活したり、押し替えが古い評価へ戻ったりする問題を修正。受け付けた順に最新の状態を保存し、別の人・別の返信の保存は並行のまま

- **パネルの画面遷移**: 設定保存・一覧取得の待機中に別のパネルへ移ると、古い操作が後から画面を上書きする問題を修正。最新の操作だけに画面更新を許可し、確定済みの保存を維持したまま、戻る操作・時間切れ・表示されなかったパネルも適切に終了
- **管理コンソールの停止操作**: 自動再起動待ち・起動中・再読み込み中のボットを、概要とサービス操作の両画面から停止できるように修正。接続前・操作中・デプロイ中・状態不明時の制限と、サービス名入力による停止確認を維持
- **返信への内部形式の混入**: 検索の利用枠超過で検索用モデルへ退避した後などに、`tool_code`・`thought`などの内部形式が返信へ混ざり、読み上げ・会話記憶にも残る問題を修正。混入した応答は破棄して同じ条件で1回だけ再生成し、解消しなければ失敗を案内。一般の`thought`の語やコード例は対象外
- **自発会話・記念日**: 生成中にOFFへ変更しても自動投稿が続く問題を修正。話題提供では会話再開・自律配信開始・間隔変更も生成前と送信前に確認し、中止した投稿は処理済みにせず次回へ持ち越す。同じ巡回の後続チャンネルにも現在の条件を適用
- **文書ワーカーの起動時復旧**: 一時的なDB障害で中断タスクの復旧に失敗すると、再起動まで処理されない問題を修正。復旧成功まで待機付きで再試行してから通常処理を開始し、連続失敗中も停止・キャンセルに対応
- **読み上げの通信期限**: gTTSへの退避時に接続・読み取り期限を設定し、通信待機で後続の読み上げが止まり続ける問題を修正。合成期限超過・キャンセル時も同期処理とバッファの回収を待ってから次へ進む
- **デプロイの起動確認**: 再起動後のPIDとログのPIDを照合し、旧プロセスやPID不明の「ログイン成功」を誤採用する問題を修正。待機中と成功確定直前のプロセス差し替え・自動再起動を検出し、巻き戻し後にも同じ確認を適用
- **サービス操作とデプロイの排他**: 起動・停止・再起動のSSH応答待ちに、別タブからデプロイやサービス操作・接続変更を同時実行できる問題を修正。共通のロックで直列化し、実行直前に接続先を再確認。送信済み操作はキャンセル時も終了まで待機
- **管理コンソールの終了**: Windowsで専用画面を閉じた際、バックエンドの終了処理を迂回して強制終了する問題を修正。進行中デプロイの完了・巻き戻しとSSH切断を待ち、期限を超えた場合だけ強制終了してログへ結果を記録
- **デプロイの通信失敗**: コードの取り込み後にSSH応答が失われても、実際のコミットを再確認して必要な巻き戻しを実行。状態を確認できない場合は未変更と断定せず、復旧できなかったことを案内
- **記憶圧縮**: 一人分の読込・保存失敗で後続ユーザーの圧縮まで止まる問題を修正。失敗したユーザーの原データと生成失敗回数を保ち、障害解消後に再処理。失敗が続く場合は巡回を打ち切って次回へ持ち越す
- **ボイス接続の切替**: `/join`で既存接続の切断に失敗した場合、保留中の応答に失敗を案内。切断結果が不明なまま新しい接続を作らず、同一チャンネルの接続再利用・ステージ昇格・権限事前確認を維持
- **読み上げの待機キュー**: 接続切替や同じ接続でのチャンネル移動後に、以前の通話向けの返信を読み上げる問題を修正。投入時の接続とチャンネルを照合し、同一チャンネルの接続再利用時は待機中の返信を維持
- **通常会話の受付制限**: 入力AI判定・画像読込より前に利用者別の期間内受付数とサーバー別・全体の同時実行数を制限。DMにも適用し、満杯の入力は待機や追加のGemini呼出しを作らず、理由に応じた案内を利用者ごとに一定期間で1回だけ返信。分岐・失敗・中断時も実行枠を回収
- **添付画像の展開上限**: 写真や縦長のスクリーンショットは長辺2048px以下へ縮小して受付。JPEGは縮小デコードを使い、形式別の元画素数・寸法の絶対上限、取得前後の圧縮サイズ・枚数・縮小後のRGB合計を制限。配信終了後も読込済み画像を再利用して二重の展開を防止
- **管理コンソールのデプロイ**: デプロイのコマンドだけ応答期限・中断後も遠隔の終了とチャネル回収を待ち、取り込み・依存更新と巻き戻しの競合を防止。終了未確認時は状態不明を保持してデプロイ・サービス操作を停止し、概要・ログ・DB閲覧と再接続は利用可能
- **旧設定の移行**: `.env` の生成で権限の設定に失敗しても警告だけで鍵を書き込んでいた問題を修正。作成時から600の一時ファイルへ書いて置き換える形にし、権限・書き込み・置き換えのどこで失敗しても既存の`.env`を残して中止する
- **統計の送信前の管理者確認**: 他の利用者の会話統計・発言回数ランキング・フィードバック集計を、描画や集計の待機中に管理者のロールが外されても送ってしまう問題を修正。送信の直前にサーバーから最新のメンバー情報を取り直して確認し、取得できない場合も送らない
- **記憶圧縮の巡回の負荷**: 一時会話ログの利用者別の取得・削除が全件を走査していたため、利用者・追記順の索引を追加（DBの版13）。利用者が増えても、巡回のたびに全ログを読み直さない
- **夏時間をまたぐ繰り返しリマインダー**: 基準のタイムゾーンを夏時間のある地域（例: `America/New_York`）へ変えた場合、夏時間の終了で同じ時刻が二度現れる時間帯に停止明けの次回時刻が過去になり、同じ繰り返しを見回りのたびに取り直す問題を修正。次回時刻はUTCで現在と比べて未来まで進め、曖昧な時刻は1回目を採用。夏時間の開始で存在しない時刻（02:30→03:30）へずらした回の翌回からは元の時刻へ戻す。既定の`Asia/Tokyo`では動作は変わらない
- **管理コンソールのペルソナ表示**: `personas.json`が無い・`default`を省略した・`default`のファイルが無い構成で、ボットは先頭のペルソナで応答しているのにサーバー画面が「—」や存在しないファイル名を表示する問題を修正。サーバー上の`prompts/`からボットと同じ規則で実効のペルソナを推定して表示し、既定に従っている場合は「（既定）」を添える。保存したファイルが見つからない場合は保存値を注記で分けて示し、ペルソナが無いときは組み込みの標準であることを表示。ボットが一覧を読み直す時点の都合で、直後のファイルの追加・削除は反映前のことがある旨も案内。ボット本体は変更せず、実ブラウザ・SSH・Discordでの確認は含まない

## 内部修正

- **会話統計の解析**: 同じユーザー・同じ発言サンプルの実行中解析を共有し、強制更新の同時要求もまとめる。新しい結果を古い解析で上書きせず、他ユーザーの記録や削除・収集設定の変更を妨げない。失敗・キャンセル後の再試行にも対応
- **共通処理への集約**: リマインダーの送信権限の確認を自発会話・記念日と同じ判定へ統一し、親密度の保存パラメータ・保存用のUTC時刻文字列（秒精度）・文書だけの依頼に使う質問文を1か所に集約。文書キューの登録時刻だけは同じ1秒の到着順を保つためマイクロ秒を維持
- **管理コンソールの表示名取得**: テーブルの中身を開くとき、表示中の行に出てくる利用者だけの表示名を取得するように変更し、記録が増えても全件を読まないように改善
- **ブロック解除パネル**: 機能ハブから独立したモジュールへ分離し、キャラ設定・自発会話の確定とブロック解除の結果を確かめる単体テストを追加
- **背景処理・終了処理**: ボットごとに周期処理と背景タスクを管理し、終了時は新規受付を停止。同期処理・文書の遠隔ファイル・音声・所有するステージ枠の後片付けを待ってからDiscord・Gemini・DBを閉じ、重複した終了要求や繰り返しのキャンセルでも回収を継続
